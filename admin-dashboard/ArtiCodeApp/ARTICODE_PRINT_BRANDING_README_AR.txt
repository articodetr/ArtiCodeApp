تحديث ترويسة الطباعة حسب حالة الاشتراك

الفكرة:
- إذا كان اشتراك المستخدم فعالاً أو تجريبياً أو قريب الانتهاء: يتم استخدام ترويسة/شعار العميل الخاصة به في السندات وكشف الحساب.
- إذا انتهى الاشتراك أو تم إلغاؤه أو لا يوجد اشتراك: يتم استخدام ترويسة ArtiCode الموجودة داخل التطبيق تلقائياً.
- عند تجديد الاشتراك تعود ترويسة العميل تلقائياً بدون أي تعديل يدوي في التطبيق.

الملفات التي تم تعديلها:
1) utils/logoHelper.ts
   أضيف فحص تلقائي لحالة الاشتراك قبل تحميل ترويسة الطباعة.

2) supabase/migrations/20260502020000_subscription_print_branding.sql
   أضيفت دالة app_get_print_branding_status التي تخبر التطبيق هل يستخدم ترويسة العميل أو ترويسة ArtiCode.

3) APPLY_PRINT_BRANDING_PATCH.sql
   نسخة جاهزة للتنفيذ مباشرة من Supabase SQL Editor.

طريقة التطبيق على قاعدة البيانات:
1) افتح Supabase Dashboard.
2) ادخل SQL Editor.
3) انسخ محتوى ملف APPLY_PRINT_BRANDING_PATCH.sql.
4) اضغط Run.

مهم:
يجب أن تكون تحديثات الاشتراكات السابقة مطبقة أولاً، خصوصاً جدول admin_subscriptions ودالة admin_dashboard_effective_subscription_status.

طريقة التجربة:
1) ادخل التطبيق بحساب مستخدم لديه ترويسة خاصة.
2) افتح حركة مالية أو تحويل واضغط طباعة السند.
3) إذا كان الاشتراك فعالاً ستظهر ترويسة العميل.
4) من الداشبورد ألغِ الاشتراك أو اجعل تاريخ النهاية قبل تاريخ اليوم.
5) ارجع للتطبيق واضغط تحديث/إعادة توليد السند أو افتح السند مرة أخرى.
6) يجب أن تظهر ترويسة ArtiCode بدلاً من ترويسة العميل.
7) فعّل الاشتراك مرة ثانية واجعل تاريخ النهاية مستقبلياً.
8) افتح السند مرة أخرى وسترجع ترويسة العميل تلقائياً.
